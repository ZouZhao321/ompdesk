# 转写是虚拟列表，条目以一轮为单位

会话转写交给 `react-virtuoso`，它只挂载可见范围，首屏定位到最后一条并对齐视口底部，挂载量与会话长度无关。首屏起点在列表挂载时读一次，之后条目增减不重设，短会话仍从顶部排下来。列表的「对齐到末端」只把最后一条数据项的底边对上视口底，页脚插槽（阶段提示、待执行命令预览）在它之后，所以首屏与主动回底在定位后再补一次滚动元素自身的底部滚动：页脚在定位那一刻可能还没提交或还没量到高度，按元素实测的滚动高度落到真正的底部，回底不会差出页脚那一截。

分组由 `lib/transcript-items.ts` 一次性算出扁平条目数组并缓存，列表只消费结果，不参与判定。一个条目覆盖一段连续消息：锚点（用户消息或 Compaction 摘要）、可见过程消息、正式回答、正式回答之后的尾部。shell 执行（`bashExecution`）与其他过程消息一样计入可见过程消息，折叠过程组不会让它和输出消失。没有正式回答的一轮与运行中的最后一轮按消息逐条渲染，`isStandalone` 决定界面是否折叠过程组，分组判定本身不变。列表要的条目键与首屏下标只由分组结果算，流式合成项的键固定追加，流式数据块因此不重建键数组。

流式消息没有 entryId，不能参与分组，由 `lib/transcript-live-tail.ts` 作为固定键的合成项接在条目数组末尾；没有流式消息时原数组引用不变，只有末尾这一项随数据块重建。

展开状态与延迟内容不存在组件内部：`lib/transcript-view-state.ts` 按「会话 id + 本轮锚点 entryId + 部位标识」保存，条目滚出视野被卸载后重建仍是用户最后一次的选择。思考块取回内容后连正文一起存下，重建的首帧直接渲染正文，既不重放加载过程也不再请求；已有正文时正文优先于加载态与错误文案，重新请求失败也不会把手里的正文盖掉。视图状态里已有正文时就不再要求会话 id，正文不会因为会话还没落盘而变成错误文案。条目键里带着会话 id，所以这条只说「读取已有的正文」：还没落盘的会话落在空桶里，切到有 id 的会话后空桶被清理，条目再重建时重新请求。没有会话 id 的新会话共用一个空桶；流式合成项没有 entryId，锚点取当前最后一轮的键，与流结束定稿的那一轮共用同一个桶。模块级仓库有数量上限，超出后按写入顺序淘汰最久没写过的条目（读取不刷新顺序），优先丢掉只带正文的条目——展开状态是用户的选择，正文可以重新取回；淘汰真的带走了展开状态时补一次通知，已挂载的订阅方不会停在旧快照。转写切到别的会话时只留下当前会话的条目，会话被删除时清掉它的桶，长会话与多条会话都不会让正文无限堆积。

滚动跟随用列表自己的跟随输出，开关由「自动跟随 / 用户上滚」状态给出，判定在 `lib/transcript-follow.ts`：只有用户自己驱动的滚动才改开关——上滚离开底部即关闭跟随，贴着底滚回来则恢复；发送提问与执行 shell 命令一律恢复跟随并把视图带到末尾，「跳到最新」滚到列表末尾，跳转到某一轮则关闭跟随让「回到底部」按钮出现。程序化定位带动的滚动（回底与跳转的落点、列表自行贴底、内容增高引起的位移）说明不了用户意图，一律不改开关，跳转落在贴底距离内也不会把刚关掉的跟随又打开。列表的贴底阈值与 hook 的判定用同一个 `FOLLOW_BOTTOM_THRESHOLD_PX`（72px），两边不会对「还在底部」给出不同答案。主动回底与跳转都先清掉用户的滚动意图窗口，紧接着的程序化滚动不会被判成又一轮用户上滚。定位全部交给列表的「滚到第 N 项」，不自行换算像素。

提问跳转条与列表并列，贴在 820px 对话列右外侧的 36px 车道，绝对定位、不参与布局。它拿同一份条目数组挑出带提问的锚点，圆点数据不重新扫描消息；当前轮由列表报告的顶部可见条目决定。圆点为 6px、中心距 14px，容器最高 180px，超出后容器内部滚动并按量到的可见高度把当前圆点滚到正中。跳转条的位置、宽度、提示间距与隐藏阈值都由 `.chat-transcript-region` 上的自定义属性派生（版心 820px、内边距 16px、车道 36px、缝隙 6px、最小留白 4px、提示间距 8px），样式里不再出现手抄的派生像素值：左缘相对转写区中线的偏移 = 版心一半 + 内边距 + 缝隙 = 432px，最小转写区宽度 = 2 ×（该偏移 + 车道 + 最小留白）= 944px。车道容器铺满转写区、只承载容器查询，转写区宽度不到 944px 就整条隐藏，移动档媒体查询再隐藏一次，两条都在首帧生效；不支持内联尺寸容器查询的浏览器由 `@supports not (container-type: inline-size)` 回退收起，不会恒显示并压住正文右缘。隐藏时跳转条自己报告状态，列表的滚动帧不再为它测量。容器查询的条件里写不了 calc，阈值按最小宽度减一写成字面量，测试按车道 36px、缝隙 6px、最小留白 4px 与行盒常量算出它并校验 CSS。版心与内边距由 `lib/transcript-rail.ts` 的 `RAIL_COLUMN_WIDTH_PX` / `RAIL_COLUMN_PADDING_PX` 给出，`ChatWindow` 的行盒、空会话的占位居中块与输入列的版心都直接读这两个常量，CSS 变量保持同值，测试校验两边一致。

跳转只把条目下标交给列表，附近的行实测高度出来后再对齐一次：列表报告停止滚动或 `lib/transcript-rail-jump.ts` 的兜底定时器到期，先到的那条清算，同一次跳转只重定位一次——点击已经在顶部的圆点不产生滚动，目标同样会被清掉。

列表不嵌套第二层虚拟化；工具输出、代码块、图片、展开收起都由列表测量高度，不预设固定高度。会话地图与跳转条各司其职，地图不入列表。
