# 转写是虚拟列表，条目以一轮为单位

会话转写交给 `react-virtuoso`，它只挂载可见范围，首屏定位到最后一条并对齐视口底部，挂载量与会话长度无关。首屏起点在列表挂载时读一次，之后条目增减不重设，短会话仍从顶部排下来。
列表的「对齐到末端」只把最后一条数据项的底边对上视口底，页脚插槽（阶段提示、待执行命令预览）在它之后，所以首屏与主动回底在定位后再补一次滚动元素自身的底部滚动：页脚在定位那一刻可能还没提交、也可能还没量到高度，这里不量页脚，
直接把滚动位置推到上限（`scrollTo({ top: Number.MAX_SAFE_INTEGER })`），由浏览器夹到当前的滚动高度，回底不会差出页脚那一截。

分组由 `lib/transcript-items.ts` 一次性算出扁平条目数组并缓存，列表只消费结果，不参与判定。一个条目覆盖一段连续消息：锚点（用户消息或 Compaction 摘要）、可见过程消息、正式回答、
正式回答之后的尾部。shell 执行（`bashExecution`）与其他过程消息一样计入可见过程消息，折叠过程组不会让它和输出消失。过程组里含 provider 错误时最新一轮的这一组默认展开，
轮中部的错误横幅不会只剩一个计数；历史轮即使曾出错后重试成功也回到折叠，首屏挂载量不随错误轮数增长。没有正式回答的一轮与运行中的最后一轮按消息逐条渲染，`isStandalone` 决定界面是否折叠过程组，分组判定本身不变。
列表要的条目键与首屏下标只由分组结果算，流式合成项的键固定追加，流式数据块因此不重建键数组。

流式消息没有 entryId，不能参与分组，由 `lib/transcript-live-tail.ts` 作为固定键的合成项接在条目数组末尾；没有流式消息时原数组引用不变，只有末尾这一项随数据块重建。

展开状态与延迟内容不存在组件内部：`lib/transcript-view-state.ts` 按「会话 id + 本轮锚点 entryId + 部位标识」保存，条目滚出视野被卸载后重建仍是用户最后一次的选择。
思考块取回内容后连正文一起存下，重建的首帧直接渲染正文，既不重放加载过程也不再请求；已有正文时正文优先于加载态与错误文案，重新请求失败也不会把手里的正文盖掉。视图状态里已有正文时就不再要求会话 id，
正文不会因为会话还没落盘而变成错误文案。视图状态的键里带着会话 id，展开状态与正文按会话分桶，所以这条只说「读取已有的正文」：还没落盘的会话落在空桶里，切到有 id 的会话后空桶被清理，条目再重建时重新请求。
没有会话 id 的新会话共用一个空桶；流式合成项没有 entryId，锚点取当前最后一轮的键，与流结束定稿的那一轮共用同一个桶。模块级仓库有数量上限，超出后按写入顺序淘汰最久没写过的条目（读取不刷新顺序），
优先丢掉只带正文的条目——展开状态是用户的选择，正文可以重新取回；淘汰真的带走了展开状态时补一次通知，已挂载的订阅方不会停在旧快照。转写切到别的会话时只留下当前会话的条目，会话被删除时清掉它的桶，
长会话与多条会话都不会让正文无限堆积。

滚动跟随用列表自己的跟随输出，开关由「自动跟随 / 用户上滚」状态给出，判定在 `lib/transcript-follow.ts`：暂停只认用户自己驱动的滚动——上滚离开底部即关闭跟随；
恢复只看位置——回到贴底距离内就恢复，不看是谁带的、也不看离用户最后一次操作过了多久，触控惯性与拖滚动条到底因此都能把跟随带回来。发送提问与执行 shell 命令一律恢复跟随并把视图带到末尾，与「回到底部」按钮走同一条路；
切分支或切叶是整段替换消息，列表不重挂、也不会触发追加跟随，重新载入成功只记一张票号，React 提交新条目后再等两帧（一帧给提交、一帧给列表量到新高度）才按 `load` 事件落到底部，
视图落在新分支的末尾而不是按旧列表高度算出的末端；这次整段替换同时作废还在路上的跳转——旧的条目下标在新列表上没有对应位置，按它再对齐会把刚回到底部的视图拽回旧轮次；跳转到某一轮则关闭跟随让「回到底部」按钮出现，
空闲期跳转停掉的跟随同样能点回来，用户把视图滑回底部也会自愈。「回到底部」按钮有两个来源：跟随暂停，或列表停稳后的确认帧实测不在底部——跟随开着而列表没跟上时也留一个恢复入口。按钮位置只有一个来源，就是那个确认帧：
列表自己的 `atBottomStateChange` 不接进状态，它在跟随途中、首屏与 load 回底的程序化滚动里同样报 false，按它落状态会把按钮钉出来；确认帧等列表停稳后再读一次自己的滚动位置。
滚动观测不看会话是否在跑，空闲期的位置改变同样参与判定。跳转自己的落点由列表滚出来，这串位置说明不了用户意图，用一次性抑制器挡住：跳转开始时合上，列表停止滚动或跳转的兜底定时器松开，重定位时继续合着，
所以落在贴底距离内也不会把刚关掉的跟随又打开。抑制器另带截止时间：调用方漏了松开，滚动观测到点自己收回，跟随不会因此永久停摆。内容增高引起的位移不是用户操作，远离开底部也不判暂停。
列表的贴底阈值与 hook 的判定用同一个 `FOLLOW_BOTTOM_THRESHOLD_PX`（72px），按钮的确认帧读的也是这个口径，三处不会对「还在底部」给出不同答案。主动回底先清掉用户的滚动意图窗口，
紧接着的程序化滚动不会被判成又一轮用户上滚。定位全部交给列表的「滚到第 N 项」，不自行换算像素。

提问跳转条与列表并列，贴在 820px 对话列右外侧的 36px 车道，绝对定位、不参与布局。定位祖先是 `.chat-transcript-region` 规则自己声明的 `position: relative`，
不靠行盒上的 Tailwind 类兜底，那个类被删掉也不会让跳转条静默改挂到整列上。它拿同一份条目数组挑出带提问的锚点，圆点数据不重新扫描消息；每条用户提问一个圆点，只有图片或附件的提问用占位文案，压缩摘要这类非提问锚点不出圆点，圆点数因此与用户提问数一致；当前轮由视口顶部所在的已挂载条目决定，行顶落在视口顶边下方一行以内仍算顶部可见（跳转落位留的余量因此仍高亮目标轮）；视图停在贴底阈值内时改取最后一个圆点——最后一段短于视口时顶部可见条目仍停在上一轮，高亮不因此倒回倒数第二个。圆点为 6px、节距与行高上限 14px，
圆点列铺满上下两条按钮之间的可用高度：空间足够时每条 14px，圆点多到放不下时按数量压缩节距，全部圆点始终露出并与提问一一对应；节距变小时圆点尺寸同步缩小，相邻圆点不会连成实线。均分后节距低于 6px 时整条跳转条收起：这样的命中区已经点不中，留着只会误导。每个圆点的行高就是它的命中区，14px 是空间足够时的上限，低于 WCAG 2.5.8 的 24px 目标——这是为紧凑排布与一一对应付出的取舍；提问很多时命中区跟随节距变小，
相邻命中区正好相接，不重叠也不留死区，不再用伪元素向外扩——扩出来的部分与邻点重叠，重叠带只归后画的那个点，实测的有效命中高度反而不齐。视觉上圆点间距取 14px，不再为命中区放大。
跳转条的位置、宽度、提示间距与隐藏阈值都由 `.chat-transcript-region` 上的自定义属性派生（版心 820px、
内边距 16px、车道 36px、缝隙 6px、最小留白 4px、提示间距 8px），样式里不再出现手抄的派生像素值：左缘相对转写区中线的偏移 = 版心一半 + 内边距 + 缝隙 = 432px；
最小留白是普通间距——转写区隐藏滚动条（`.chat-session-scroll` 写 `scrollbar-width: none`，旧 Chromium 由 `::-webkit-scrollbar` 兜底隐藏），
跳转条不需要为滚动条让位。最小转写区宽度 = 2 ×（该偏移 + 车道 + 最小留白）= 944px。车道容器铺满转写区、只承载容器查询，转写区宽度不到 944px 就整条隐藏，移动档媒体查询再隐藏一次，两条都在首帧生效；
不支持内联尺寸容器查询的浏览器由 `@supports not (container-type: inline-size)` 回退收起，不会恒显示并压住正文右缘。隐藏时跳转条自己报告状态，列表的滚动帧不再为它测量。
转写区窄于 944px 时跳转条与滚动条同时缺席，这一档没有滚动位置提示，是已知取舍。
顶部可见条目的测量与滚动共用一个 rAF 调度，列表的 `itemsRendered` 只触发这次测量、几何在测量帧里直接读已挂载的行：流式期间每个数据块都会报告一次已渲染条目，在报告里直接读尺寸等于每个块都强制布局两次。容器查询的条件里写不了 calc，
阈值按最小宽度减一写成字面量，测试按车道 36px、缝隙 6px、最小留白 4px 与行盒常量算出它并校验 CSS。
版心与内边距由 `lib/transcript-rail.ts` 的 `RAIL_COLUMN_WIDTH_PX` / `RAIL_COLUMN_PADDING_PX` 给出，`ChatWindow` 的行盒、
空会话的占位居中块与输入列的版心都直接读这两个常量，CSS 变量保持同值，测试校验两边一致。

悬停与聚焦提示是 `aria-hidden` 的浮层，位置只写进 DOM、不进状态，锚点由圆点元素给出。位置在锚点变化时算一次，之后随滚动重新对准并在失去锚点时收起；缩放、面板拖拽、字体加载与圆点增减都不发滚动事件，
提示可见期间另用 `ResizeObserver` 观察竖条与圆点列，尺寸一变就重新对准，圆点数组变化时再校验一次锚点是否还在。

跳转只把条目下标交给列表，附近的行实测高度出来后再对齐一次：列表报告停止滚动或 `lib/transcript-rail-jump.ts` 的兜底定时器到期，先到的那条清算，
同一次跳转只重定位一次——点击已经在顶部的圆点不产生滚动，目标同样会被清掉。转写被整段替换时待清算目标直接作废并松开抑制器，旧下标不会在新列表上被清算。

列表不嵌套第二层虚拟化；工具输出、代码块、图片、展开收起都由列表测量高度，不预设固定高度。会话地图与跳转条各司其职，地图不入列表。
