# AGENTS.md 的写法

`AGENTS.md` 每次会话都会加载，每一行都在占用上下文。它只放两样东西：会改变行为的
规则，以及指向别处材料的索引。这份说明的判据来自 `skill://writing-for-agents` 与
`skill://domain-modeling`。

## 三问定性质

- 提交一次代码，这句话会变吗？会变，是快照。
- 换一台机器，这句话还成立吗？不成立，是快照。
- 依赖升一个版本，这句话还成立吗？不成立，是快照。

三条都过关的是规则。规则靠人做决定才失效，快照靠下一次提交就失效。

## 三类内容各归其位

- 规则（怎么做、禁止什么）：写进正文。团队共享的进 `AGENTS.template.md`，本机工作流进 `AGENTS.md`，例如 worktree 起点、提交标题、检查范围。
- 决策（为什么这样选、放弃了什么）：留在维护者本机，不写进仓库。
- 快照（当前有哪些文件、取值多少）：写进 `docs/file-map.md`，或索引指向的来源，例如路由清单、索引规模、色值。

## 索引写成 skill 清单

omp 加载 skill 时用的是「名字: 描述」的一行一条清单。索引照这个格式写：

```
- `路由与接口方法`: 查某个网址由哪个文件处理、支持哪些方法；来源 `app/api/` 目录结构，`git ls-files 'app/api/**/route.ts'`
```

三条要求：

1. 名字后面必须有描述，说明它约束什么、什么时候用。只写名字的条目不成立：读者为了判断要不要用，就得把目标整个读一遍。
2. 描述先给结论，再给时机。读者不打开目标也能做对判断。
3. 清单与来源逐字一致：改一处必须同时改另一处。

## 维护动作

- 新增决策：记在维护者本机，不写进仓库。
- 新增或删除文件：改 `docs/file-map.md` 对应小节。
- 新增快照类别：在 `AGENTS.md` 的快照索引追加一行，并给出能直接执行的读取命令。
- 新增规则：团队共享的写进 `AGENTS.template.md`，本机的写进 `AGENTS.md`。一句话说不清的，通常是决策，去写 ADR。

## 校验

- 写进索引的读取命令必须先跑通：跑不通的命令等于没有索引。
- 预算：`wc -l -c AGENTS.md` 与 `wc -l -c AGENTS.template.md` 相加。当前 203 行约 11.9KB；明显变大时先怀疑有人把快照放回来了。

## 反面

- 表格：三列以上要横向对齐，一行读不完。清单从左到右就是一句话。
- 生成块：工具写进文档的段落，工具一跑就被覆盖，里面的数字还会随状态变化。
- 机器绝对路径、具体会话 id、轮数与消息数：换一个读者就无法执行或核对。
- 计数：任何「有 N 个」都要能说出测量方式，说不出就删掉。
